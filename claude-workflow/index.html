我的 Claude 工作法

我用 Claude 做過五種工作：設定環境、競品分析、提案簡報、規格文件、追蹤 AI 新訊。每一種都整理成一條可以重複跑的流程。我的原則是：同一件事做到第二次，就把它做成範本。

01 · SETUP

先花一次力氣設定好，之後每次對話都用得到

預設的 Claude 每次開新對話都不記得我是誰、要什麼格式、做事有什麼規矩。我把這些寫進檔案和工具，只要設定一次。

CLAUDE.md：寫給 AI 的工作守則

每次對話都會自動載入。內容包括我的角色、預設技術環境、輸出格式，以及 14 條品質守則。

  • 固定輸出順序：先給可以直接用的產出，再說明
  • 資料不夠就停下來列出缺什麼，不用假設硬補
  • 引用的數字要標來源，沒來源就標「未驗證」
  • 用 /plan /diff /snap 這類短指令直接切換模式

Superpowers：讓 Claude 照工程流程做事

Superpowers 是一套 skill 外掛，強迫 Claude 按固定階段工作，不會一收到需求就開始寫。

  • brainstorm：先問清楚需求
  • write plan：拆成小步驟，我確認後才動手
  • execute：交給 subagent 逐步執行
  • verify：跑過驗證才能說「完成」

Skill 與 MCP：把 SOP 和資料接進來

重複的任務用 skill-creator 包成 skill，例如台灣在地 UX 訪談、產品經理工具箱。再用 MCP 接上 Google Drive、Gmail、Figma、GitHub、ClickUp，Claude 就能直接讀寫資料，我不用再手動複製貼上。

手機遠端控制：離開電腦也能繼續跑

在專案資料夾執行 claude remote-control，或在正在跑的 session 裡輸入 /remote-control。之後用手機上的 Claude app 就能接手同一個 session：看進度、回覆問題、下一步指令。這份提案簡報大部分的修改就是這樣在路上完成的。

CLAUDE.md（節錄）
### 輸出順序（固定）
① 可直接使用的產出 → ② 說明與分析 → ③ 替代方案（僅在真正重要時寫）

### R7｜不確定就停，不猜
缺少關鍵輸入時：停下，列出「我需要哪些資訊」，不用假設填充後繼續

### 縮寫觸發詞
/plan  輸出執行計劃（≤ 3 句），待確認再展開
/snap  輸出 已完成 / 待處理 / 未解決
/diff  只輸出修改段落，不輸出全文
工作流程
  1. 寫 CLAUDE.md角色、環境、輸出格式、品質守則、觸發詞。每次覺得「又要講一遍」就補進去。
  2. 裝 Superpowers讓複雜任務一定先釐清需求、出計劃、確認，再動手。
  3. 接 MCP connectorDrive、Gmail、Figma、GitHub、ClickUp。資料來源在哪，就接到哪。
  4. 重複的任務包成 skill同一種任務做過兩次，就用 skill-creator 整理成 skill。
  5. 開 Remote Control長任務在電腦上跑，人離開座位後用手機接手。
CLAUDE.mdSuperpowersskill-creatorMCP connectorsRemote Control
Take away

最值得先做的兩件事：寫 CLAUDE.md、裝 Superpowers。

CLAUDE.md 讓你不用每次重新交代規矩。Superpowers 讓 Claude 先想清楚再動手。這兩件設定完，後面每一種工作流程的品質都會提高。

02 · BENCHMARK

競品分析：先定比較框架，再抓資料，最後轉成推薦

以前的競品分析是截幾張圖、寫感想，很難回答「所以我們該怎麼做」。現在的做法是：用同一把尺量每一家，再把結論轉成選機推薦規則。

工作流程
  1. 定比較框架先決定要比哪些面向。以 AI 產品頁為例：網頁定位、功能介紹、資訊安全、硬體導流、SEO／FAQ。
  2. 用腳本抓完整頁面請 Claude 寫 Puppeteer 腳本，在 1920px 寬度下慢慢捲動整頁，等圖片載完再全頁截圖，另外存一份手機用的縮小版。
  3. 切區塊、標分類把每一家的長頁面切成區塊，每個區塊對應到框架裡的一個分類，最後整理成同一張比較表。
  4. 篩出相容產品整理自家產品規格，依功能需要的硬體條件篩出支援的機型，取代一長串相容清單。
  5. 轉成推薦卡把篩出來的真實機型、官方產品照放進 mockup 的比較表和推薦卡。
Claude CodePuppeteersharp比較框架產品規格表

實例：Apple Intelligence、Samsung Galaxy AI、ASUS 的 AI 產品頁比較。推薦卡用的是實際篩選出來的機型。

Take away

先定比較框架再抓資料，每個推薦都要能對回一項證據。

抓頁面的腳本可以重複用，競品改版時重跑一次就能更新比較表。

03 · PROPOSAL

Mockup 和線上簡報：做成可以點的網頁，用 git 管理版本

靜態投影片講不清楚動態的 hero 和互動效果，改版時也很難知道每一版改了什麼。所以我把提案直接做成網頁：mockup 是真的可以動的 HTML，簡報是一個範本引擎。

簡報範本化：引擎和內容分開

engine/deck.js 負責畫面和換頁，裡面沒有任何專案專屬的內容。每份提案只要改 deck.config.js：章節、頁面、要框出的重點區域，全部寫在設定檔裡。

另外寫了 check-config.js 檢查設定：檔案是否存在、框選範圍有沒有超出頁面、規格欄位有沒有漏填。

Mockup：多個方向一起比較

Hero 一次做五個方向（A–E），加上一個比較頁，大家可以直接點開來看。角色動畫用 three.js 做成可以操作的 3D 模型，提供走路、揮手、點頭、跳躍等動作。需要交給設計師時，再轉進 Figma。

工作流程
  1. 在本機開發用 .claude/launch.json 啟動本機伺服器，Claude 改完就能馬上預覽。
  2. 每次修改都 commit每個 commit 寫清楚改了什麼、為什麼改。改壞了隨時可以退回上一版。
  3. 大改版就開新資料夾v3/ 和舊版並存，舊連結不會失效。圖片網址加版本參數，避免瀏覽器讀到舊的快取。
  4. 推上 GitHub Pagesgit push 之後網站自動更新，把連結給大家就能看最新版本，手機會自動切成輕量模式。
  5. 內部筆記不公開設計筆記放在 docs/，並加進 .gitignore，不會跟著發佈出去。
HTML mockupthree.jsFigmagitGitHub PagesRemote Control
Take away

提案本身就是可以操作的原型，而簡報是一個可以重複使用的範本。

換下一個專案時，引擎和檢查工具直接沿用，只要換設定檔和內容。用 git 保留每一版，客戶問「上一版是什麼樣子」時，隨時都答得出來。

04 · REVERSE SPEC

逆向工程：把既有產品拆回規格文件

既有的 app 或頁面常常沒有完整規格，規則只存在畫面裡或某個人腦中。我請 Claude 一格一格拆畫面，把看得到的東西寫回文件。

工作流程
  1. 蒐集素材截圖、錄影、實際頁面，加上官方說明與影片。
  2. 拆出畫面和功能列出每個畫面、每個區塊，以及使用者在上面能做的事。
  3. 套進固定欄位每個區塊都用同樣六個欄位描述：目標、素材、比例、範圍、資產、敘事。競品和自家產品用同一張表，拿來比較就很直接。
  4. 產出規格頁規格寫在資料檔 spec-data.js，簡報和規格頁讀同一份資料，所以兩邊的內容一定一致。
  5. 找人確認缺口看不出來的規則（後端邏輯、例外狀況）列成問題清單，找負責的人確認後補上。
截圖／錄影六欄位規格表spec-data.jscheck-config.js
Take away

先固定規格的欄位，再請 AI 填內容。

欄位固定之後，缺了什麼一眼就看得出來，檢查腳本也能自動抓漏填的地方。AI 負責拆解和整理，看不出來的規則交給人判斷。

05 · CROSS-CHECK

AI 新訊：ChatGPT 排程收集，兩個模型互相查核

AI agent 的消息一週就變一次，自己追不完，只看單一模型的整理又怕有錯。所以一邊負責定期收集，兩邊再互相挑錯。

工作流程
  1. ChatGPT 排程收集設定排程任務，定期整理 AI agent 相關新訊，產出摘要。
  2. Claude 查證並補充把摘要交給 Claude，逐條找第二個來源，標出互相衝突和查不到出處的內容。
  3. 回到 ChatGPT 互評把 Claude 的查證結果拿回給 ChatGPT，請它反駁或補充。兩邊都同意的才列為結論。
  4. 讓兩個模型直接對話除了手動轉貼，也讓兩個模型直接交換資訊，減少我來回搬運的時間。
  5. 篩出和工作相關的行動最後由 Claude 挑出和手上專案有關的項目，轉成待辦或 skill 的更新。
ChatGPT 排程任務Claude雙向互評
Take away

一個模型負責收集，兩個模型互相挑錯。

單一模型整理的資訊可能有幻覺，讓另一個模型挑錯最便宜。雙方都有來源、也都同意的內容，我才拿來用。

總結

把每一套工作流程做成範本

上面五個流程有一個共通點：做第一次時順手留下可以重複用的東西，第二次就從範本開始。

CLAUDE.md

對話規則的範本。每次開新對話都自動套用。

線上簡報引擎

提案的範本。換專案時只換設定檔和內容。

抓頁面腳本

競品分析的範本。競品改版時重跑一次就更新。

六欄位規格表

規格文件的範本。競品和自家產品用同一套欄位。

  • 01每次要重新交代的規矩，就寫進 CLAUDE.md。
  • 02同一件事做到第二次，就做成範本或 skill。
  • 03AI 說完成不算完成，要另外跑一次驗證，或請另一個模型檢查。
