# 建議研究配置：Acer Extensa / TravelMate 45–60 秒筆電廣告模板

> 本文件由 Claude 與 Codex 討論整理（Codex 原文見 `codex_reply_q4.md`）。標「Claude 補充」者為我的意見；標「待驗證」者為假設，不是結論。

## 1. 研究問題與假設

核心問題：**單一 key spec 如何在有限秒數內被看懂、被相信，並順暢接到下一個賣點？**

待驗證假設（Codex）：
1. 「情境＋證據」比「規格字卡」更容易被理解。
2. 每個 spec 模組約 5–9 秒可容納「主張＋證據」。
3. 共用人物或場景能降低模組拼接感。

限制：影片分析只能建立「表現手法」假設；理解度、可信度需用腳本預演或小型觀眾測試驗證。

## 2. 三層（四層）資料模型

```
賣點主題（例：日常便攜）
  └ key spec（最小單位：重量、厚度、續航…）
      └ 模組實例（某支影片裡「怎麼表現這個 spec」的一段）
          └ 鏡頭（shots，已有逐鏡總表）
```

- 同一個 spec 在不同影片的不同表現，要分成不同「模組實例」，不要混成一筆。
- 一個賣點主題可有多個 spec；一個 spec 也可能服務多個主題（例：重量同時支援「便攜」與「耐用通勤」）。

### key spec 初始詞表（商務／便攜筆電）

重量、厚度、續航、快充、耐用、CPU／多工、記憶體、儲存、AI 功能、螢幕、連接埠、無線連線、視訊／收音、資安、維修／管理。
「性價比」不是 spec，另列為**定位標籤**。

### 每個模組實例要記錄的欄位

文案表述、規格值與條件（SKU／地區／測試條件）、證據類型、起訖與時長、鏡數、運鏡、景別、構圖、燈光、字卡風格、產品出鏡比例、聲音、素材型態（實拍／CGI／螢幕錄影）、來源影片與信心度。

證據類型受控詞：情境暗示、數字宣稱、測試展示。
便攜類常見畫面證據（供標註）：單手提起、放入背包、秤重／重量字卡、厚度對比、跨時段使用＋電量數字、通勤場景。

## 3. 樣本配置

### 分階段（Claude 補充：把 Codex 的 12 支拆成兩步，控制人工量）

| 階段 | 內容 | 目的 |
|---|---|---|
| 0（已完成） | Apple MacBook Air M5、ASUS Zenbook DUO | 驗證流程 |
| 1（建議下一步） | 再補 **6–8 支**，其中 **Acer 3–4 支**（TravelMate／Extensa／Aspire 商用或日常款官方影片）、Dell／Lenovo／HP／Surface 各 1–2 支商務輕薄款 | 找到最貼近 Extensa／TravelMate 的基準，完成第一輪 key-spec 模組庫 |
| 2 | 擴至約 24 支，依「缺少的 spec」補樣 | 補齊詞表缺口，歸納模板區間 |

Codex 建議的 pilot 12 支結構：Acer 4、Dell 2、Lenovo 2、HP 1、Surface 1，加上已分析的 Apple、ASUS。

### 篩選原則

- 優先**官方 30–90 秒成片**；商務、教育、日常性價比款至少占 **2/3**，不用旗艦硬湊。
- 素材型態目標（pilot）：實拍主導／混合／CGI 主導 ≈ 6／4／2。
- 同一品牌不超過總數 1/3。片源不足的 spec 保留為「缺口」，不補不相關的片。
- 469 秒的 ProArt RTX Spark 只作局部技法參考，**不納入節奏比較**。
- 目前的 96 支清單偏 Apple／ASUS 旗艦與創作款，**不能直接當作 Extensa／TravelMate 的基準**；需要另外擴充爬蟲涵蓋 Acer、Dell、Lenovo、HP、Surface。
- Acer 官方將 TravelMate、Extensa 歸類於「行動商務」，可作為核心基準。

## 4. 可組合的產出

### (A) 45–60 秒時間軸骨架（初始假設，由資料再校正）

| 區段 | 占比 | 45 秒 | 60 秒 |
|---|---|---|---|
| Hook | 10% | 約 4.5 秒 | 約 6 秒 |
| 主張／情境 | 15% | 約 7 秒 | 約 9 秒 |
| spec 證據模組 | 60% | 約 27 秒（3 個模組） | 約 36 秒（4 個模組） |
| 收尾（標語＋品牌） | 15% | 約 7 秒 | 約 9 秒 |

各區段可浮動約 ±5 個百分點，總和維持 100%。
Claude 補充：這組比例是 Codex 依經驗給的起點，**不是從 Apple／ASUS 兩支算出來的**（Apple 約 38% 為字卡與 UI，ASUS 約 30%），要等第 1 階段資料出來再用實際分布替換。

### (B) key-spec 模組卡（可填空）

```
主題＿ ／ spec＿ ／ 利益文案＿ ／ 證據＿ ／ 秒數＿ ／ 鏡頭＿ ／ 字卡＿ ／ 聲音＿ ／ 前後銜接＿ ／ 適用型號＿
```

使用注意：
- 重量：單手提起＋重量字卡；
- 續航：跨時段工作＋測試條件，**不能把電量動畫當成量測證據**；
- 耐用測試不等於防摔保證；續航、AI、效能須綁定 SKU、地區、條件。

## 5. 方法分工與驗收

| 項目 | 方法 |
|---|---|
| 文字（規格、註腳） | OCR；數字與註腳一律人工確認 |
| 旁白、時間 | ASR |
| 行為、產品、證據類型 | 視覺模型判讀（連續影格，不用單張） |
| 運鏡 | 光流＋RANSAC 工具只提供候選標籤；實拍與 CGI 分開計分；CGI 再分相機／物件／背景運動 |
| 鏡頭邊界 | ffmpeg 場景分數＋人工校正 |

- 人工量：Pilot 全數人工校對，第二人複核 20%；擴充期全查數字／註腳與 CGI 運鏡，其餘抽查 25%。
- 建議門檻（待驗證）：核心 spec 分類一致率 ≥90%；鏡頭邊界誤差 ≤0.2 秒；不足就修訂標註規則。
- 現有運鏡準確率（Apple 87%、ASUS 50%，共 25 鏡、以我目視為標準）僅作個案診斷，不能當驗收結果。

## 6. 風險

- 內部下載許可 ≠ 音樂、人物、畫面可再製；研究庫保留來源，製作時重新創作。
- 標準答案目前是我（模型）的目視判讀；要作為驗收標準，需由人工標註取代。
- 同一支廣告的長短版、各地區版會重複計算，需以 campaign 分組。
- 僅憑官方成片無法得知成效，模板是「候選手法」，需 Acer 試拍或預演驗證。

## 7. 需使用者決定

1. 第一支廣告優先服務哪一類受眾：**企業採購、教育採購、個人辦公者**？（決定主題、證據畫面與語氣）
2. 首批 **SKU 與可公開宣稱的規格／測試證據**能否先鎖定？（決定能用哪些 key spec 與數字）
3. （Claude 補充）可否提供 Acer 自家 3–4 支你認為「該有的樣子」的參考影片，或指定要對標的競品品牌？

## 8. 使用者決議（2026-10-08）與調整

- 受眾：**個人辦公者**。主題優先序：便攜、續航、日常效能與多工、AI 輔助辦公、螢幕與視訊會議；「資安、維修／管理」降為次要（偏企業採購）。
- 對標：**Apple、ASUS（含輕薄款）為主體**；Dell／Lenovo／HP／Surface／Acer 自家僅作補充。
- 模板不綁定 Extensa／TravelMate，改為**跨系列的 key-spec 模組庫**，型號適用性放在模組卡的「適用型號」欄。
- 樣本調整：階段 1 以 Apple／ASUS 為主，補 6–8 支；其他品牌最多 2–3 支補充。
