建議採用「**自動量測＋逐鏡頭視覺模型標註＋人工校正**」。成果應定位為**成片的分鏡與廣告敘事分析**；實際燈具、焦段、攝影機設定與原始拍攝腳本，通常無法從 YouTube 成片可靠還原。以下僅規劃，未讀取 CSV 或實作。

**1．分析維度與方法**

「自」＝自動量測；「模」＝視覺模型判讀；「人」＝人工複核。風險指從成片推論的限制，並非工具保證的準確率。

| 維度／定義 | 可量測性與建議方法 | 準確度風險 |
|---|---|---|
| 解析度：取得檔案的像素尺寸 | 自：ffprobe 讀取寬高；另記來源版本 | 低；不能代表原片或實際細節解析力，可能經升頻 |
| fps：播放幀率與時間取樣 | 自：ffprobe，核對平均幀率及影格時間戳，辨識可變幀率 | 低～中；無法推回拍攝 fps、升格或補幀設定 |
| 影片長度：實際播放時間 | 自：容器、視訊／音訊時間戳交叉確認 | 低；CSV 秒數可能四捨五入 |
| 畫面比例：顯示比例與有效內容比例 | 自＋人：ffprobe 的 SAR／DAR；黑邊偵測與抽查 | 中；黑色場景可能誤判黑邊，片內比例可能變化 |
| 鏡頭序列：剪接單位及起訖時間 | 自＋人：PySceneDetect 初切，人工修正硬切、疊化、閃白 | 中；快速運動、閃光與 CGI 變形易誤切 |
| 運鏡：固定、平移、俯仰、推拉、環繞等 | 自＋模＋人：光流／特徵追蹤＋RANSAC 估全域運動；模型觀看連續片段 | 高；物體運動、數位縮放、CGI 相機運動易混淆 |
| 燈光：可見光向、軟硬、輪廓光、明暗配置 | 模＋人：逐鏡頭看陰影、反光、亮暗分布 | 高；只能描述效果，不能確認燈具數量、功率或布光圖 |
| 色溫：畫面冷暖及可能的照明偏色 | 自＋模＋人：可信中性區域估白點，模型標註冷／中性／暖／混合 | 高；白平衡、調色、彩色光使實際 Kelvin 難以辨識；預設不填精確 K 值 |
| 柔焦程度：畫面或主體的柔化表現 | 自＋模＋人：固定尺度下計算主體 ROI 的 Laplacian 變異數，搭配視覺分類 | 高；低紋理、景深、動態模糊、降噪與壓縮都會影響指標 |
| 對比程度：亮度分布及局部明暗差 | 自＋模：亮度直方圖、P95−P5、RMS 對比、主體／背景差異 | 中；須统一色彩轉換、排除黑邊，字幕與背景會干擾 |
| 產品類別／型號：商務、輕薄、創作、電競等 | 模＋人：CSV、標題、OCR、畫面交叉判讀；類別允許多標籤 | 中～高；相近外觀不能可靠辨識型號 |
| 腳本順序：每鏡內容與敘事功能 | 模＋人：逐鏡標註「畫面→動作→聲音／文案→溝通目的」，再整理全片結構 | 中～高；觀察到的內容與推測的創作意圖須分欄 |

ffprobe 適合取得媒體技術資料；PySceneDetect 的偵測器提供切點候選，仍需人工確認。[ffprobe 官方文件](https://ffmpeg.org/ffprobe.html)、[PySceneDetect 官方文件](https://www.scenedetect.com/docs/latest/api/detectors.html)  
光流與 Laplacian 是運動、邊緣的計算工具；上述運鏡及柔焦判定是本方案的分析設計。[OpenCV 光流文件](https://docs.opencv.org/5.0/tutorials/others/optical_flow.html)、[Laplacian 文件](https://docs.opencv.org/3.3.0/d5/db5/tutorial_laplace_operator.html)

**2．建議新增維度**

| 維度 | 建議記錄 |
|---|---|
| 鏡頭語言、景別與構圖 | 英雄鏡頭、細節特寫、使用情境、功能展示；遠／中／近／微距、角度、負空間 |
| 製作形式 | 實拍／CGI／混合／無法判定；與運鏡分開標註 |
| 剪接節奏 | ASL＝分析區間時長÷鏡頭數；另記鏡長中位數、分布及每 5 秒切點密度 |
| 轉場 | 硬切、疊化、淡入淡出、匹配剪接、動作銜接；記錄轉場區間 |
| 色彩調色盤 | 主要色、飽和度、背景與產品配色；排除黑邊並記錄抽樣方式 |
| 字幕、文案與 CTA | OCR 原文、出現時間、賣點、行動呼籲、可讀性；區分燒錄字與字幕軌 |
| 產品出鏡比例 | **可見時長占比**與**畫面面積占比**分開；另記首次完整露出時間 |
| 人物與場景 | 人物數量、使用行為、室內／戶外／棚景、情境用途 |
| 音樂與聲音 | 旁白、對白、音樂、音效、靜音；ASR 轉寫，分析聲畫同步及節拍 |
| 前 3 秒 Hook | 產品、人物、動作、問題、視覺奇觀或文字承諾；記錄實際內容 |
| 品牌露出與敘事 | Logo／品牌名首次出現、累計露出、片尾；Hook→賣點→證據→收尾／CTA，允許缺項 |

Hook 類型及剪接節奏只能描述設計，**不能在沒有成效資料時推論廣告效果**。

**3．Pipeline 與兩層 schema**

流程：  
**清單校驗 → 授權來源取得 → 技術探測 → 鏡頭初切／校正 → 特徵量測 → VLM＋OCR＋ASR → 人工覆核 → 彙整比較**

- Windows：建議 **Node 負責批次調度，FFmpeg／ffprobe 負責媒體處理**。若採 PySceneDetect、OpenCV，建議另設 Python 環境；目前不需安裝。
- 技術資料從取得檔案量測；模型使用分析代理檔。代理檔的縮放、色彩轉換與時間映射必須留紀錄。
- 每鏡提供起／中／末代表影格及短片段；長鏡頭、快速動作追加取樣。**單張截圖不足以分析運鏡與動作順序。**
- 首版人工確認全部切點；模型不確定、證據衝突及重要賣點列入覆核。

| 層級 | 建議欄位 |
|---|---|
| 每支影片 `videos` | `video_id`、YouTube ID、品牌、系列／型號、標題、上傳日期、廣告年份及依據、URL、語言／地區、campaign／版本群組、授權狀態、來源取得日期／雜湊、寬高、fps、VFR、比例、時長、codec／色彩資訊、鏡頭數、ASL、產品出鏡率、Hook／敘事摘要、處理及覆核狀態 |
| 每個鏡頭 `shots` | `video_id＋shot_id`、順序、起訖時間／影格、時長、轉場區間、證據影格／片段路徑、畫面描述、動作、景別／構圖、運鏡、實拍／CGI、燈光、冷暖、柔焦／對比指標、色盤、產品／人物／場景、OCR／ASR 時段、音樂／音效、敘事功能、覆核結果 |

所有判讀欄位附帶：`method、evidence、confidence、review_status`；另保存工具／模型／提示詞／schema 版本。`unknown`、`not_applicable`、`failed` 分開，避免把缺資料當成零。

輸出建議：**JSONL 保存完整巢狀資料，videos.csv＋shots.csv 供比較，HTML 分鏡時間軸供人工檢閱**。時間以秒及原始時間戳為準，鏡頭採起點包含、終點不包含。

**4．分階段執行與驗收**

1. **定義標註規則**：先用 3 支差異明顯的影片校準術語；確認年份、鏡頭邊界及產品出鏡定義。
2. **Pilot 12 支**：MacBook、Zenbook、Vivobook、ROG、TUF 各至少 2 支，另選 2 支高難度案例；盡量跨五年、短／長版、實拍／CGI、快剪／慢剪。
3. **建立人工基準**：12 支全部人工校切點；其中 4 支由兩人獨立標註後討論定稿。
4. **達標後擴至約 95 支**：凍結規則與版本；覆核低信心／失敗項，並抽查至少 10% 影片。
5. **比較報告**：按系列、年份、片長、廣告形式分組；同 campaign 的長短版避免重複加權。

Pilot 建議門檻，均屬**待驗證目標**：

- 技術欄位及來源紀錄完整率 100%；鏡頭時間無缺口、無重疊。
- 硬切邊界在 ±2 影格內的 precision／recall 均 ≥95%；漸變轉場另評起訖區間。
- 主要分類標籤 macro-F1 ≥0.85；主觀標籤人工一致性 κ ≥0.70，未達標則合併或重定義類別。
- CTA／品牌文字逐一人工確認；產品出鏡時長占比誤差 ≤5 個百分點。
- 記錄每支處理費用、人工分鐘數及失敗率，再估全批成本；色溫與柔焦先驗證分類一致性，不驗收「真實攝影參數」。

**5．風險與限制**

- **公開可觀看不等於可任意下載或再利用。** YouTube 條款限制下載與使用方式；先確認平台允許方式及所需權利人許可。內部分析、雲端模型上傳、對外引用片段應分別確認。[YouTube 官方條款](https://www.youtube.com/static?template=terms)
- YouTube 轉碼、壓縮、HDR／SDR 轉換可能改變細節與色彩；量測反映的是取得版本。
- 成片無法唯一還原燈光色溫、焦段、光圈、柔焦濾鏡或原始運鏡；CGI 尤其需要保留「無法判定」。
- 模型可能幻覺型號、文案與創作意圖；結論須能回指時間段及證據。
- 上傳年不一定是廣告製作年；官方影片也可能包含教學、發表會或產品介紹，需先篩選。
- 樣本數與片長不均、地區版及重剪版本會扭曲品牌比較；約 95 支只能代表目前收集的樣本。
